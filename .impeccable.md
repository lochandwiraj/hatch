## Design Context

### Users
Indian college students (18–24) hunting for hackathons, design competitions, case challenges, workshops, and startup competitions. Used on laptops during study sessions and on mobile while commuting. Primary job: discover relevant events fast, register without friction, track what they signed up for.

### Brand Personality
- **Three words**: Ambitious · Focused · Energetic
- Tone: direct, slightly competitive — like a friend who always knows about the best opportunities. Not corporate. Not playful. Purpose-driven.
- HATCH = hatch a plan, hatch a career. The brand is about potential turning into action.

### Aesthetic Direction
- **Theme**: Dark — students use this late at night, in dark dorm rooms, in competitive coding sessions
- **Vibe**: Premium dark SaaS meets Luma event discovery. Deep `#050508` backgrounds, `#111111` cards, floating pill navigation
- **Font pairing**: Qepho Modern (HATCH wordmark only) + Plus Jakarta Sans (all body copy)
- **Primary accent**: Violet (`#7c3aed` → `#6366f1` gradient for CTAs, `#a78bfa` for text accents)
- **Tier system colors** (must be consistent everywhere):
  - Free → zinc (`#71717a` dot, `#a1a1aa` text)
  - Explorer → sky (`#38bdf8` dot, `#7dd3fc` text)
  - Professional → emerald (`#34d399` dot, `#6ee7b7` text)
- **Category color system**: Each event category maps to a distinct gradient (hackathon=purple-blue, design=pink-violet, tech=blue-indigo, business=amber-red, etc.)
- **Anti-references**: No generic Bootstrap/Material admin UI. No light-mode SaaS. No rainbow gradients. No glassmorphism overuse.

### Design Principles
1. **Image-first cards** — every card leads with a full-bleed color gradient or poster image, like Luma. The visual is the hook.
2. **Restrained color** — Accent colors are earned. Only tier indicators and CTAs use the brand palette; everything else is zinc/white on near-black.
3. **No gradient text** — Absolute ban. Solid colors only for all text. Weight and size create hierarchy.
4. **One motion register** — FadeUp on scroll entry is the only entrance animation. Button `whileHover`/`whileTap` is the only persistent micro-interaction. No bouncing, elastic, or decorative motion.
5. **Consistent token use** — CARD, CARD_INNER, INPUT_STYLE inline constants mirror the design tokens. Hard-coded deviations are bugs, not customizations.
